## A self-study course, built to be finished alone

This site is the whole course. Every module is one page you can read in a sitting, and every page ends with something
you can check: a laboratory with stated success criteria, exercises with model answers, and a knowledge check. Nothing
requires a lecture, a licence or a paid API — the notebooks run on a laptop CPU.

It is written for **BS Data Science students** in years three and four who have completed introductory machine
learning, and for self-learners with Python experience who want to move from training models to securing them. No
cybersecurity background is assumed: Module 01 builds the vocabulary from first principles.

## Inside a module

Every module page uses the same layout, so you always know where you are:

| You see | What it gives you |
|---|---|
| **A module card** at the top | Level, study hours, prerequisite and status, plus links to the lab, exercises, quiz and reading |
| **Learning objectives** | What you can do afterwards, stated as capabilities rather than topics |
| **Theory and worked examples** | The argument developed, with Mermaid diagrams each carrying a text description |
| **Runnable Python** | Code with expected output, fixed seeds and no network calls |
| **Practical exercises** | Recall, apply and extend — in that order |
| **Knowledge check** | Collapsible questions with answers and reasoning |
| **Previous / next module** | Two links at the foot of the page, so the pathway is never lost |

## What you need

One machine, one Python environment, no cloud account.

| Requirement | Detail |
|---|---|
| **Python 3.12+** | Validated on 3.14.7; every version is pinned in `requirements-labs.txt` |
| **Core libraries** | NumPy, pandas, scikit-learn, PyTorch (CPU build), Jupyter |
| **Security tooling** | None beyond the pinned stack: the attack, detection and integrity code is written in the course |
| **Serving** | FastAPI and httpx for the API modules; the service runs in-process or on localhost |
| **Optional** | Docker for containment labs, Ollama for a local LLM, SQLite FTS5 for retrieval |
| **Hardware** | 8 GB RAM is sufficient; a GPU is never required and never assumed |

## Study safely and ethically

!!! warning "Authorisation comes first"

    The offensive techniques here exist so you can defend against them. Every laboratory targets data, models and
    applications that you own or that are supplied inside the course sandbox.

    Nothing in this course authorises testing any system you do not own or have written permission to test.
    Unauthorised testing is a criminal offence in many jurisdictions and a breach of professional ethics everywhere.
    [Read the full safety and ethics statement →](getting-started/index.md#safety-and-ethics)

!!! info "A note on honesty"

    This is a living course. Every module page states its own status. Where a defence is weak, the page says so.
    Where a technique stopped working because tooling changed, it is marked historical rather than quietly deleted.
    Where a framework has been revised, the version and access date are recorded.

    That habit is the subject itself: a security claim is only worth the evidence behind it.
