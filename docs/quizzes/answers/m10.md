## Multiple-choice explanations

**1. M10-Q01** — correct answer **C: How closely the substitute agrees with the target's predictions**

Fidelity is agreement with the target, which is what the attacker is buying; accuracy against labels is a different property that the target itself may not have.

- **A** — Query counts describe cost, which is reported alongside fidelity.
- **B** — Label accuracy measures the substitute as a product, not as a copy.
- **D** — Size is an implementation choice, not a measure of copying.

**2. M10-Q02** — correct answer **B: It removes the gradient-like signal, so more queries are needed for the same fidelity**

A probability vector carries confidence across all classes, while a label is one bit; removing it raises the query budget required to fit a boundary.

- **A** — A label reveals one decision, not the shape of the boundary.
- **C** — Extraction from labels is possible, just more expensive.
- **D** — The class count is unchanged by the output format.

**3. M10-Q03** — correct answer **A: It spends queries where the substitute's uncertainty is highest, near the boundary**

The decision boundary is where information concentrates; querying near it resolves more uncertainty per label than sampling the input space uniformly.

- **B** — A substitute is still trained; it just receives better-chosen queries.
- **C** — Equivalence is not guaranteed by any sampling strategy.
- **D** — Rate limiting is a separate constraint the attacker must still respect.

**4. M10-Q04** — correct answer **D: Adding per-account query quotas**

A quota bounds the information an attacker can buy over time, which is the resource extraction consumes, and it leaves the model untouched.

- **A** — Class count is a property of the task, not a control.
- **B** — That changes the model and may reduce utility.
- **C** — Retraining changes the target and does not limit queries.

**5. M10-Q05** — correct answer **C: Extraction becomes somewhat harder, and the effect must be measured rather than assumed**

Rounding removes precision but leaves ordering, so it raises cost modestly; the size of the effect depends on the model and must be measured against an unrounded baseline.

- **A** — Ordering information remains, which is what most extraction uses.
- **B** — Legitimate accuracy is largely unaffected by output rounding.
- **D** — The endpoint still answers; the format changed.

**6. M10-Q06** — correct answer **B: The suspect model was trained on the protected model's outputs**

A watermark is evidence of derivation, which is a technical finding; functional similarity and legal infringement are separate questions decided by inspection and by law.

- **A** — Derivation does not imply equivalence.
- **C** — Infringement is a legal determination, not a watermark result.
- **D** — Watermarking has no effect on future extraction.

**7. M10-Q07** — correct answer **A: The target itself is only about 0.71 accurate, so copying it well reproduces its errors**

Fidelity measures agreement with the target, including its mistakes; a faithful copy inherits the target's error rate.

- **B** — A high-fidelity copy is working as intended.
- **C** — The two metrics measure different things and generally differ.
- **D** — More queries improve fidelity rather than damaging it.

**8. M10-Q08** — correct answer **D: Many queries concentrated near a decision boundary with near-duplicate inputs**

Extraction looks like systematic probing of a region, so query similarity plus boundary concentration distinguishes it from volume alone.

- **A** — Volume alone is ambiguous: a batch job can be legitimate.
- **B** — Endpoint diversity suggests exploration, not boundary fitting.
- **C** — Time of day is weak evidence in a global service.

**9. M10-Q09** — correct answer **C: A distilled student is still a queryable model that can be extracted in turn**

Distillation changes who owns the copy, not whether query access allows copying; the student inherits the same exposure on its own endpoint.

- **A** — Size affects cost marginally but is not the reason.
- **B** — An API is still the delivery mechanism for most deployments.
- **D** — Distillation preserves the teacher's behaviour, which is the point.

**10. M10-Q10** — correct answer **B: The trigger set is published with the detection procedure**

Independent verification requires a reproducible test: a defined trigger set, a stated response and a decision rule that another party can run.

- **A** — Secrecy prevents independent verification and weakens the evidence.
- **C** — Documentation is not a watermark.
- **D** — A watermark should not degrade utility, and accuracy is irrelevant to checkability.

## Written model answers

<div class="sas-answer" id="m10-s1-answer"><p class="sas-item__head"><strong>M10-S1</strong> <span class="sas-meta">Short answer · 3 marks</span></p><p class="sas-answer__q">Define extraction fidelity and state the baseline it should be reported against.</p><p class="sas-answer__label">Model answer</p><p>Fidelity is the fraction of inputs on which the substitute's prediction matches the target's prediction, measured on held-out inputs. It should be reported against the target's own accuracy and against a trivial baseline such as the majority class, so a high number cannot be confused with a useful copy.</p></div>

<div class="sas-answer" id="m10-s2-answer"><p class="sas-item__head"><strong>M10-S2</strong> <span class="sas-meta">Short answer · 3 marks</span></p><p class="sas-answer__q">Name two properties of an API that determine extraction cost, and explain the direction of each.</p><p class="sas-answer__label">Model answer</p><p>Output granularity: probabilities carry more information per query than labels, so coarser output raises cost. Query budget: a per-account limit caps total information, so a tighter quota raises the time and accounts needed. Both act on information per unit time rather than on the model itself.</p></div>

<div class="sas-answer" id="m10-c1-answer"><p class="sas-item__head"><strong>M10-C1</strong> <span class="sas-meta">Conceptual · 5 marks</span></p><p class="sas-answer__q">Explain why extraction is an information-acquisition problem rather than a model-stealing problem, and what follows for defence.</p><p class="sas-answer__label">Model answer</p><p>The attacker never needs the weights: they need enough input-output examples to fit a function that agrees with the target on the inputs they care about. That reframes defence around the information channel, which is why quotas, coarser outputs, monitoring and authentication matter more than weight encryption. It also explains why fidelity plateaus: once the substitute captures the boundary, extra queries buy little, so the defender's target is to keep the plateau above the attacker's budget.</p></div>

<div class="sas-answer" id="m10-c2-answer"><p class="sas-item__head"><strong>M10-C2</strong> <span class="sas-meta">Conceptual · 5 marks</span></p><p class="sas-answer__q">Compare watermarking and query monitoring as responses to extraction, on evidence, cost and limitations.</p><p class="sas-answer__label">Model answer</p><p>Watermarking provides after-the-fact evidence of derivation: a trigger set that the suspect model answers in the protected model's distinctive way, checkable by a third party if the procedure is published. It costs a small training intervention and does not prevent the copy. Monitoring provides during-the-fact detection: per-principal volume, query similarity and boundary concentration, which can trigger a quota or a block. It costs instrumentation and produces false positives. Neither prevents extraction; together they shorten the window and support a claim, and the honest position is that they raise cost rather than closing the channel.</p></div>

<div class="sas-answer" id="m10-sc1-answer"><p class="sas-item__head"><strong>M10-SC1</strong> <span class="sas-meta">Scenario-based · 6 marks</span></p><p class="sas-answer__q">A startup offers a credit-scoring API with a generous free tier returning full probabilities. Design a defence package with costs and the residual risk you would report to the board.</p><p class="sas-answer__label">Model answer</p><p>Reduce output to a score band for the free tier, keep probabilities for contracted clients under audit, and set a per-account daily quota with anomaly detection on query similarity. Add a watermark trigger set during training and a published verification procedure. Costs are product changes for the free tier, instrumentation for monitoring, and a small training intervention. Residual risk: a patient attacker with many accounts can still approximate the banding function, and a contracted client can extract within quota, so the board should be told the copy is delayed rather than prevented.</p></div>

<div class="sas-answer" id="m10-sc2-answer"><p class="sas-item__head"><strong>M10-SC2</strong> <span class="sas-meta">Scenario-based · 6 marks</span></p><p class="sas-answer__q">You suspect a competitor's model was distilled from yours. Describe the technical evidence you would gather and the limits of each item.</p><p class="sas-answer__label">Model answer</p><p>Run the watermark trigger set and record the response rate against a control model. Compare behaviour on a stratified probe set: agreement far above what independent training would produce, especially on atypical inputs where two models usually disagree. Check error patterns, which are inherited more faithfully than correct predictions. Preserve query logs showing systematic probing if available. Limits: agreement can arise from shared training data or a common architecture, watermarks can be removed by fine-tuning, and none of this establishes legal infringement, which needs counsel and discovery.</p></div>

<div class="sas-answer" id="m10-p1-answer"><p class="sas-item__head"><strong>M10-P1</strong> <span class="sas-meta">Practical programming · 8 marks</span></p><p class="sas-answer__q">Implement extraction against a mock API at budgets 50, 150 and 500 queries, report fidelity on held-out data, and compare probability output with label-only output at the same budget.</p><p class="sas-answer__label">Model answer</p><p>A complete implementation wraps the target in a counting API, samples queries around the observed feature ranges, fits a substitute (ridge for probabilities, a classifier for labels) and measures agreement with the target on held-out rows. It reports a table of budget against fidelity and a paired comparison at one budget. The expected finding is rising then plateauing fidelity, and probability output beating labels at equal budget. A strong answer also reports the target's own accuracy, so fidelity is not mistaken for quality, and notes that query sampling determines the ceiling.</p></div>

<div class="sas-answer" id="m10-ct1-answer"><p class="sas-item__head"><strong>M10-CT1</strong> <span class="sas-meta">Critical thinking · 6 marks</span></p><p class="sas-answer__q">A product owner argues that model extraction does not matter because the model will be obsolete in a year. Construct the response.</p><p class="sas-answer__label">Model answer</p><p>Obsolescence shortens the window but not the harm: a competitor who copies a model can sell it at a lower price for that year, and the copied artefact persists after the original is retired. Extraction also exposes the training investment and the decision logic to probing, which supports adversarial and privacy attacks on the same API. The counter-argument is not that the model is eternal but that the cost of copying falls as queries accumulate, so the defender's task is to keep the required budget above the attacker's patience for as long as the model carries value.</p></div>

<div class="sas-answer" id="m10-ct2-answer"><p class="sas-item__head"><strong>M10-CT2</strong> <span class="sas-meta">Critical thinking · 6 marks</span></p><p class="sas-answer__q">You are asked to approve publishing a paper that describes an extraction attack on a commercial API. What conditions would you attach?</p><p class="sas-answer__label">Model answer</p><p>Require that the target is either the authors' own system or a provider that has given written authorisation, that the paper reports the vendor's response and any mitigation applied, and that no proprietary data or weights are disclosed. Require the query volume to stay within published terms, and evidence that the provider was notified before publication so they could patch. Refuse if the work would leave an unpatched capability public with no coordination, or if the API's terms prohibit the queries, because reproducibility does not override authorisation.</p></div>
