## Multiple-choice explanations

**1. M20-Q01** — correct answer **D: It evaluates named evidence against declared thresholds and blocks with a reason**

A gate is a mechanical decision over evidence; if it cannot block or cannot name the failing item, it is a checklist with no authority.

- **A** — Review is a separate control and is not reproducible.
- **B** — Manual triggering guarantees it will be skipped under pressure.
- **C** — Exhaustive lists do not produce decisions.

**2. M20-Q02** — correct answer **C: Comparison of the new model's outputs against the live model without affecting users**

Shadow mode mirrors traffic to the new model and discards its decisions, which measures behavioural difference safely; a canary exposes a small share of real users.

- **A** — Shadow mode duplicates compute, so it is usually more expensive.
- **B** — Rollback is a separate mechanism.
- **D** — No deployment pattern confers immunity.

**3. M20-Q03** — correct answer **B: That the running artefact matches the expected digest and behaves like the reference**

Tags are mutable labels; verification requires a digest comparison and a behavioural check on a probe set, because a substituted artefact can serve happily.

- **A** — Image existence is an inventory fact.
- **C** — The URL proves reachability, not integrity.
- **D** — Log collection is observability, not integrity.

**4. M20-Q04** — correct answer **A: The assumptions that, if false, would defeat the argument**

An argument is only as strong as its premises, so naming them tells a reader where to challenge it and tells the team what to monitor.

- **B** — Cost matters for decisions but does not make the argument valid.
- **C** — Tooling is implementation detail.
- **D** — A date does not affect validity.

**5. M20-Q05** — correct answer **D: Because detection is imperfect, so the ability to revert bounds the duration of harm**

No gate catches everything, so recoverability is the control that limits how long a bad release affects users.

- **A** — Rollback restores previous behaviour; it does not improve accuracy.
- **B** — Rollback depends on monitoring to trigger it.
- **C** — Specific requirements vary and are not the reason here.

**6. M20-Q06** — correct answer **C: A recorded waiver naming the risk, the approver, the compensating control and an expiry**

Waivers are legitimate when they are explicit, owned and time-bounded; an unrecorded waiver is indistinguishable from a control that never existed.

- **A** — Verbal agreement leaves no accountable record.
- **B** — Removing the gate hides the risk from future releases.
- **D** — Re-running until a flaky result passes is not a decision.

**7. M20-Q07** — correct answer **B: A signed attestation linking the image digest to the source commit and build**

Provenance needs a verifiable link between what runs and how it was produced, which an attestation provides and prose does not.

- **A** — A README is documentation of intent.
- **C** — A changelog is human-readable history.
- **D** — A screenshot cannot be verified at deploy time.

**8. M20-Q08** — correct answer **A: 'Reduce indirect-injection tool-call success from 40 % to under 5 % on a 20-payload suite, with the residual documented'**

A testable scope names the behaviour, the measurement, the target and the residual, which is what allows the work to be evaluated and repeated.

- **B** — An adjective cannot be measured.
- **C** — Best practices are inputs, not outcomes.
- **D** — Implementing everything spreads effort and produces no measurable result.

**9. M20-Q09** — correct answer **D: Because it reports an absence and does not state what was tested, how, or what was excluded**

Absence claims need scope and method to mean anything; without them the reader cannot tell a thorough assessment from a shallow one.

- **A** — The problem is the form of the claim, not an assumption about prevalence.
- **B** — It generalises poorly to AI systems for the same reason.
- **C** — Clarity is not the issue.

**10. M20-Q10** — correct answer **C: Utility and robustness metrics, ACL and injection test results, artefact hashes and the waiver record**

The bundle should let a reviewer verify each claim without rerunning the project, which requires measured results, integrity evidence and decisions.

- **A** — Neither supports a technical claim.
- **B** — Process artefacts are context, not evidence of properties.
- **D** — Commercial terms are unrelated.

## Written model answers

<div class="sas-answer" id="m20-s1-answer"><p class="sas-item__head"><strong>M20-S1</strong> <span class="sas-meta">Short answer · 3 marks</span></p><p class="sas-answer__q">Explain in two sentences why a green dashboard is not evidence that a release is safe.</p><p class="sas-answer__label">Model answer</p><p>A dashboard reports availability and error rates, which can be healthy while the model behaves wrongly or a substituted artefact serves traffic. Safety evidence is a comparison against expected behaviour and identity, neither of which a status page measures.</p></div>

<div class="sas-answer" id="m20-s2-answer"><p class="sas-item__head"><strong>M20-S2</strong> <span class="sas-meta">Short answer · 3 marks</span></p><p class="sas-answer__q">Name the two verification steps that close a model deployment and say what each catches.</p><p class="sas-answer__label">Model answer</p><p>Digest verification against a signed manifest catches a substituted or modified artefact. Behavioural comparison on a fixed probe set catches a correctly hashed artefact that nonetheless behaves differently, for example because configuration or preprocessing changed.</p></div>

<div class="sas-answer" id="m20-c1-answer"><p class="sas-item__head"><strong>M20-C1</strong> <span class="sas-meta">Conceptual · 5 marks</span></p><p class="sas-answer__q">Explain how a release gate, a deployment pattern and a rollback plan divide the work of managing release risk.</p><p class="sas-answer__label">Model answer</p><p>The gate decides whether the evidence meets the threshold before exposure, so it addresses known requirements. The deployment pattern bounds exposure when the gate is wrong: shadow mode measures without affecting users, and a canary limits the population if behaviour degrades. The rollback plan bounds duration, restoring the previous artefact and behaviour once detection occurs. Each covers a different failure: missing evidence, unanticipated behaviour and imperfect detection. A programme with only a gate relies on the gate being both complete and correct, which no gate is.</p></div>

<div class="sas-answer" id="m20-c2-answer"><p class="sas-item__head"><strong>M20-C2</strong> <span class="sas-meta">Conceptual · 5 marks</span></p><p class="sas-answer__q">A capstone proposes to 'audit' a system. Explain how to turn that into a testable scope with measurable claims.</p><p class="sas-answer__label">Model answer</p><p>An audit becomes testable when it names the system and version, the threat families in scope, the tests and their success criteria, and the evidence that will be produced. For example: run a 20-payload injection suite against the production template with fixed sampling, measure tool-call and disclosure success separately, run the ACL suite, verify artefact hashes, and report each result with its configuration and residual. The deliverable is then a set of numbers and reproduction steps, not an opinion, which is what allows a reader to check the work.</p></div>

<div class="sas-answer" id="m20-sc1-answer"><p class="sas-item__head"><strong>M20-SC1</strong> <span class="sas-meta">Scenario-based · 6 marks</span></p><p class="sas-answer__q">Design the release gate for a customer-facing assistant with a refund tool: name six gates, their evidence and one failure each blocks.</p><p class="sas-answer__label">Model answer</p><p>Utility: task accuracy above a threshold, blocking a model that cannot do the job. Injection: tool-call success at zero on the payload suite, blocking a launch where text can move money. Authorisation: cross-tenant denial test passing, blocking data exposure. Privacy: membership leakage below a threshold on a measured attack, blocking a model that memorises customers. Integrity: manifest hash match, blocking a substituted artefact. Coverage: red-team matrix completed with gaps recorded, blocking an unexamined launch. Each gate names its producing test and its threshold, so the decision is mechanical and the reason is legible.</p></div>

<div class="sas-answer" id="m20-sc2-answer"><p class="sas-item__head"><strong>M20-SC2</strong> <span class="sas-meta">Scenario-based · 6 marks</span></p><p class="sas-answer__q">A model passes every gate at 09:00 and misbehaves by 15:00. Describe the deployment design that would have limited the harm.</p><p class="sas-answer__label">Model answer</p><p>Shadow mode first, comparing outputs on live traffic against the current model and flagging divergence before any user is exposed. Then a canary to a small, monitored cohort with automatic rollback on behavioural triggers such as refusal rate, tool-call rate or probe-set mismatch. Monitoring must include the probe set as a synthetic canary that runs continuously, because the misbehaviour may not raise errors. The design bounds exposure to the canary population and duration to the detection latency, which is the point of the pattern.</p></div>

<div class="sas-answer" id="m20-p1-answer"><p class="sas-item__head"><strong>M20-P1</strong> <span class="sas-meta">Practical programming · 8 marks</span></p><p class="sas-answer__q">Implement a release gate that reads an evidence dictionary, applies eight thresholds with directions, blocks on missing evidence, and emits a per-gate reason.</p><p class="sas-answer__label">Model answer</p><p>A complete implementation defines gates with id, metric, threshold and direction, treats a missing key as blocked rather than skipped, and returns a table with value, status and the rule applied. The decision is release only when every gate passes. Tests cover a complete passing set, a missing item, a value below an 'above' threshold and a value above a 'below' threshold, asserting the decision and the reason in each case. A strong answer records the source path for each evidence item so a reviewer can open the artefact.</p></div>

<div class="sas-answer" id="m20-ct1-answer"><p class="sas-item__head"><strong>M20-CT1</strong> <span class="sas-meta">Critical thinking · 6 marks</span></p><p class="sas-answer__q">You are the accountable owner signing a residual-risk acceptance. What would make you refuse to sign, and what would you require instead?</p><p class="sas-answer__label">Model answer</p><p>Refuse when a claim rests on an untested control, when a gate is waived without a compensating control or expiry, when the residual is unquantified, or when nobody owns monitoring after launch. Those conditions make the signature a statement about hope rather than evidence. Require, instead, the measured results with their configuration, a named post-launch owner with authority to roll back, a monitoring plan with thresholds and a re-test date. Signing is defensible only when the evidence exists and the assumptions are written down where the next reviewer can challenge them.</p></div>

<div class="sas-answer" id="m20-ct2-answer"><p class="sas-item__head"><strong>M20-CT2</strong> <span class="sas-meta">Critical thinking · 6 marks</span></p><p class="sas-answer__q">A capstone is assessed on 'security improvement'. Propose the rubric you would use, including what would score zero.</p><p class="sas-answer__label">Model answer</p><p>Score four things: whether the claim is measurable with a stated baseline and target; whether the evidence is reproducible, including seeds, versions and exact configuration; whether the work considers an adaptive attacker rather than only the original payload set; and whether residual risk and limitations are stated honestly. Zero would be awarded for unmeasured assertions, for results that cannot be reproduced, for a defence declared effective without an attack designed against it, or for evidence that is copied rather than produced. The rubric rewards the same discipline the course teaches: a claim is a measurement plus its scope.</p></div>
