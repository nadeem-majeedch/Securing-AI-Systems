## Multiple-choice explanations

**1. M12-Q01** — correct answer **A: A retrieved web page contains instructions the model follows**

Indirect injection arrives through content the model reads rather than through the user's message, which is why the attacker need not be the user at all.

- **B** — That is direct injection: the attacker is the person typing.
- **C** — Role-play is a jailbreak technique, not indirect injection.
- **D** — Malformed JSON targets the parser, not the instruction channel.

**2. M12-Q02** — correct answer **D: Both arrive as tokens in one sequence, with no enforced privilege marker**

Any separation is conventional formatting learned during training, so text that looks like an operator message can be treated as one; enforcement must happen in code.

- **A** — Training data is full of instructions, which is why the model follows them.
- **B** — Instruction following is the capability being exploited.
- **C** — Attention covers the whole context, including the system prompt.

**3. M12-Q03** — correct answer **C: Separation by capability and the exact success criterion used**

Success means different things for disclosure, tool calls and policy violations; averaging them hides which control failed and makes runs incomparable.

- **A** — Model choice for the harness is irrelevant to the metric's meaning.
- **B** — Payload length is a descriptive detail.
- **D** — Date matters for currency, not for interpretation.

**4. M12-Q04** — correct answer **B: Removing the email capability from the assistant's tool set**

Capability removal is enforcement: if the tool does not exist, no phrasing can invoke it, whereas the other options are text-level conventions and blocks.

- **A** — Tags are formatting and are routinely ignored by the model.
- **C** — An instruction in the prompt competes with the injected text.
- **D** — A phrase filter misses paraphrases and other languages.

**5. M12-Q05** — correct answer **A: About 9 %**

With prevalence 0.001 and FPR 0.01, false positives outnumber true positives roughly ten to one, so precision is near 0.09.

- **B** — TPR is not precision; it ignores false positives.
- **C** — The calculation gives roughly one in eleven, not one in two.
- **D** — High TPR cannot overcome a base rate this low.

**6. M12-Q06** — correct answer **D: It is another token-level hint that injected text can contradict or override**

The statement is text, so it carries no enforcement; an attacker who writes a convincing counter-instruction competes on the same terms.

- **A** — Length is not the problem.
- **B** — The failure is independent of weight availability.
- **C** — Models handle meta-instructions well enough to be fooled by them.

**7. M12-Q07** — correct answer **C: A jailbreak targets the model's policy; exfiltration targets the application's data**

Jailbreaks aim to make the model produce prohibited content, while exfiltration aims to move data the application can reach; the same phrasing can serve either.

- **A** — Closed models are routinely jailbroken.
- **B** — No server code execution is required.
- **D** — Jailbreaks are usually direct, though content can also be indirect.

**8. M12-Q08** — correct answer **B: An output filter plus removing secrets from the prompt entirely**

If the secret is not in the context, disclosure is impossible; an output filter catches residual leakage of anything else, which is a layered control rather than a wording rule.

- **A** — A blocklist and a longer prompt are both text-level measures.
- **C** — Detection and education do not remove the secret.
- **D** — Delimiters are formatting, and user requests are not controls.

**9. M12-Q09** — correct answer **A: At realistic prevalence, false positives overwhelm the review capacity that blocking would demand**

Blocking converts every false positive into a refused legitimate request, and at low prevalence those dominate; flagging keeps a human in the loop for the ambiguous cases.

- **B** — Detectors can be accurate; prevalence is the problem.
- **C** — Blocking is technically easy and organisationally costly.
- **D** — Cost is not the argument; error distribution is.

**10. M12-Q10** — correct answer **D: The payload set, success criterion, model version and sampling parameters**

Reproduction requires the inputs, the definition of success, the model and the sampler; without the last two, a rerun can differ for reasons unrelated to the defence.

- **A** — Count and version are necessary but insufficient.
- **B** — Runtime is a cost measure.
- **C** — Severity is an assessment, not a reproduction parameter.

## Written model answers

<div class="sas-answer" id="m12-s1-answer"><p class="sas-item__head"><strong>M12-S1</strong> <span class="sas-meta">Short answer · 3 marks</span></p><p class="sas-answer__q">Define attack success rate for prompt injection and explain why it must be reported per capability.</p><p class="sas-answer__label">Model answer</p><p>Attack success rate is the fraction of payloads that achieve the attacker's stated objective under a fixed model, sampler and prompt template. It must be reported per capability because disclosure, tool invocation and policy violation are different outcomes with different controls, and an average across them hides which defence failed.</p></div>

<div class="sas-answer" id="m12-s2-answer"><p class="sas-item__head"><strong>M12-S2</strong> <span class="sas-meta">Short answer · 3 marks</span></p><p class="sas-answer__q">Give two reasons a phrase blocklist fails against injection, other than encoding tricks.</p><p class="sas-answer__label">Model answer</p><p>First, the objective can be expressed in unlimited paraphrases and languages, so the blocklist must enumerate what it cannot. Second, the harmful action is usually the capability rather than the phrase, so a polite request that triggers an email tool never matches a suspicious pattern.</p></div>

<div class="sas-answer" id="m12-c1-answer"><p class="sas-item__head"><strong>M12-C1</strong> <span class="sas-meta">Conceptual · 5 marks</span></p><p class="sas-answer__q">Explain the instruction hierarchy problem and why it cannot be solved inside the prompt.</p><p class="sas-answer__label">Model answer</p><p>Training teaches a model to follow instructions, and every instruction arrives as tokens in one context: operator rules, user requests and retrieved content are distinguishable only by convention, not by enforcement. A prompt-level rule therefore competes with any text that contradicts it, and a model has no reliable way to privilege one source when the text is adversarial. The solution must sit outside the model: remove the capability, constrain the data, validate the arguments and require confirmation, so that following a malicious instruction achieves nothing.</p></div>

<div class="sas-answer" id="m12-c2-answer"><p class="sas-item__head"><strong>M12-C2</strong> <span class="sas-meta">Conceptual · 5 marks</span></p><p class="sas-answer__q">A detector reports 92 % TPR at 0.5 % FPR on a 0.05 % prevalence stream. Explain what happens operationally and what you would recommend.</p><p class="sas-answer__label">Model answer</p><p>At that prevalence, false positives exceed true positives by roughly nine to one, so a blocking deployment would refuse about ten legitimate requests for every real attack, and the review queue would be dominated by innocent traffic. Recommend using the detector as a triage signal combined with other evidence, such as a first-seen principal or an unusual tool call, and reserve blocking for cases where a second signal agrees. Report the arithmetic with the recommendation, because the number is what convinces a product owner that automatic blocking is the wrong control.</p></div>

<div class="sas-answer" id="m12-sc1-answer"><p class="sas-item__head"><strong>M12-SC1</strong> <span class="sas-meta">Scenario-based · 6 marks</span></p><p class="sas-answer__q">A document assistant reads uploaded PDFs and can create calendar events. Design the injection controls and the test suite that would justify launch.</p><p class="sas-answer__label">Model answer</p><p>Controls: treat PDF text as data with no authority, restrict calendar creation to the user's own calendar with a confirmation step, cap event size and count, and log every tool call with the source document. Test suite: a payload corpus covering instruction override, data exfiltration through event titles, link injection and encoded variants, run against the exact production template with fixed sampling, scoring tool invocation and disclosure separately. Launch requires a measured success rate per capability, with the residual stated, not an assurance that injection is solved.</p></div>

<div class="sas-answer" id="m12-sc2-answer"><p class="sas-item__head"><strong>M12-SC2</strong> <span class="sas-meta">Scenario-based · 6 marks</span></p><p class="sas-answer__q">A customer-support bot must summarise tickets written by customers. Explain why the ticket author is a threat and what changes in the design.</p><p class="sas-answer__label">Model answer</p><p>Any customer can write instructions into a ticket, so the untrusted author chooses text the model reads with agent authority; a request to 'summarise this and refund order 1234' can reach a refund tool. Design changes: the model may read tickets but not act on them, refunds require an authenticated operator action, tool arguments are validated against the ticket's customer, and the summary is presented with a link to the source rather than as an instruction to staff. The design assumption is that ticket content is hostile, not merely noisy.</p></div>

<div class="sas-answer" id="m12-p1-answer"><p class="sas-item__head"><strong>M12-P1</strong> <span class="sas-meta">Practical programming · 8 marks</span></p><p class="sas-answer__q">Build a mock assistant with two capabilities (summarise, send_email), eight synthetic payloads and four defences; measure tool-call and disclosure success separately and assert the allowlist reaches zero tool calls.</p><p class="sas-answer__label">Model answer</p><p>A complete implementation models the assistant as a rule follower with a trace, defines payloads that ask for email and for disclosure, and evaluates each defence over the whole corpus. Metrics are computed separately: tool-call successes and disclosure successes, each as a fraction. The allowlist defence removes the email capability, so tool-call success must be exactly zero while disclosure is unaffected; the assertion follows from the design. A strong answer notes that the phrase filter barely changes either rate, which is the pedagogical point.</p></div>

<div class="sas-answer" id="m12-ct1-answer"><p class="sas-item__head"><strong>M12-CT1</strong> <span class="sas-meta">Critical thinking · 6 marks</span></p><p class="sas-answer__q">'Prompt injection is just a model problem; a better model will fix it.' Assess this claim.</p><p class="sas-answer__label">Model answer</p><p>The claim confuses a capability with a boundary. A more capable model follows instructions better, including instructions that arrive in data, so capability does not separate operator intent from attacker text. The vulnerability is architectural: untrusted content and authority share one channel. What improves is robustness to particular phrasings, which an attacker can iterate against. The fix is to make success worthless: no dangerous tools, scoped data, validated arguments and confirmation for irreversible actions.</p></div>

<div class="sas-answer" id="m12-ct2-answer"><p class="sas-item__head"><strong>M12-CT2</strong> <span class="sas-meta">Critical thinking · 6 marks</span></p><p class="sas-answer__q">You are asked to approve a launch where injection success is 2 % for disclosure and 0 % for tool calls. Make the decision and defend it.</p><p class="sas-answer__label">Model answer</p><p>Approve with conditions if disclosure is limited to content the user may already see and no secret sits in context; the 2 % then represents the model repeating visible text, which is a quality issue. Refuse if the disclosed text includes another tenant's document, credentials or a system prompt containing sensitive logic, because a 2 % rate over many requests is a certainty over time. The defence should name the residual, add an output filter for detected secrets, and set a re-test date, since a rate measured against one payload set is a lower bound on the true rate.</p></div>
