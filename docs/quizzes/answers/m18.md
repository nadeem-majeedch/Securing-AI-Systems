## Multiple-choice explanations

**1. M18-Q01** — correct answer **C: Per-principal query similarity and boundary concentration**

Extraction is systematic probing, so near-duplicate queries concentrated near a decision boundary are the signature; latency and restarts describe operations.

- **A** — Latency reflects load, not intent.
- **B** — Restarts indicate reliability problems.
- **D** — Startup accuracy is static and unrelated to traffic.

**2. M18-Q02** — correct answer **B: Alert fatigue, because ordinary clients mistype credentials constantly**

Single-event alerts on common events produce volume that no team can triage; the signal must be a rate or a pattern relative to a baseline.

- **A** — It catches noise more reliably than attacks.
- **C** — Authentication remains necessary.
- **D** — Monitoring does not affect model accuracy.

**3. M18-Q03** — correct answer **A: The filesystem and memory hold the evidence needed to establish scope and cause**

Containment removes the artefact from service while keeping a copy; destroying it first makes root cause and blast radius unknowable.

- **B** — Speed is not the reason.
- **C** — A preserved container serves no traffic.
- **D** — Accuracy is not the concern.

**4. M18-Q04** — correct answer **D: Artefact hashes match the manifest and behaviour matches the reference on a probe set**

Identity plus behaviour: the right artefact is running and it answers as expected, which uptime and a successful load do not establish.

- **A** — Availability is not integrity.
- **B** — Verbal confirmation is not evidence.
- **C** — Loading and a 200 response say nothing about what was loaded.

**5. M18-Q05** — correct answer **C: The causal mechanism, the control that failed and the change that prevents recurrence**

A review earns its cost by changing a control and naming the mechanism; without that, the same incident recurs through a different path.

- **A** — Capacity is rarely the mechanism.
- **B** — Individual blame does not prevent recurrence.
- **D** — A timeline is context, not a corrective action.

**6. M18-Q06** — correct answer **B: Treat it as a weak signal, combine it with corroborating evidence and tune the threshold against measured outcomes**

A frequent, imprecise signal can still be useful as triage if combined with others; disabling it removes coverage and raising sensitivity worsens the ratio.

- **A** — Disabling loses the signal entirely.
- **C** — Escalation without analysis creates noise at the top.
- **D** — Higher sensitivity increases false positives.

**7. M18-Q07** — correct answer **A: Removing the malicious artefact from the serving path**

Containment stops the harm; eradication removes the cause, and doing the second before the first extends the incident.

- **B** — Pipeline changes are eradication work.
- **C** — Training changes are a longer-term fix.
- **D** — Deleting records destroys evidence.

**8. M18-Q08** — correct answer **D: A canary set of referrals with known required fields, checked per deployment**

A fixed canary set with expected content checks detects omission directly and runs on every change, unlike resource metrics.

- **A** — CPU utilisation is unrelated to content correctness.
- **B** — Parameter count does not change at runtime.
- **C** — Index size is an inventory metric.

**9. M18-Q09** — correct answer **C: Because unresolved questions become the next review's scope and prevent false closure**

Stating the limits of the investigation prevents the organisation from assuming the question is settled and gives the next review something to test.

- **A** — Brevity is not the purpose.
- **B** — Findings can be sound and still incomplete.
- **D** — Accountability is not the aim.

**10. M18-Q10** — correct answer **B: The previous artefact's digest, the decision authority and the verification steps**

A rollback is an operational action under pressure, so the target artefact must be identified by digest, the authority named and the post-rollback checks defined.

- **A** — Learning rate is training detail.
- **C** — Evaluation size is measurement context.
- **D** — Support contact is not a procedure.

## Written model answers

<div class="sas-answer" id="m18-s1-answer"><p class="sas-item__head"><strong>M18-S1</strong> <span class="sas-meta">Short answer · 3 marks</span></p><p class="sas-answer__q">Explain in two sentences why 'the model is up' is not a recovery criterion.</p><p class="sas-answer__label">Model answer</p><p>Availability says a process is answering, not which artefact is running or whether it behaves correctly. Recovery requires matching the expected hashes and reproducing reference behaviour on a probe set, both of which can fail while the service returns 200.</p></div>

<div class="sas-answer" id="m18-s2-answer"><p class="sas-item__head"><strong>M18-S2</strong> <span class="sas-meta">Short answer · 3 marks</span></p><p class="sas-answer__q">Name two AI-specific detection signals that generic infrastructure monitoring would miss.</p><p class="sas-answer__label">Model answer</p><p>Query-pattern signals such as near-duplicate inputs concentrated near a decision boundary, which indicate extraction. Output-quality signals such as a rise in refusals, omissions or citation failures on a canary set, which indicate model or data corruption that resource metrics do not show.</p></div>

<div class="sas-answer" id="m18-c1-answer"><p class="sas-item__head"><strong>M18-C1</strong> <span class="sas-meta">Conceptual · 5 marks</span></p><p class="sas-answer__q">Explain how base rates change the value of an AI security alert, using a detector for prompt injection.</p><p class="sas-answer__label">Model answer</p><p>An alert's usefulness depends on how many true events exist among the traffic. At low prevalence, even a detector with a small false-positive rate produces mostly false alerts, so the team learns to ignore it and real events are missed. The remedy is to combine weak signals into a rarer composite, alert on rate changes rather than single events, and measure precision at the organisation's real prevalence. Reporting only the detection rate hides this arithmetic, which is why the base rate belongs in the alert design document.</p></div>

<div class="sas-answer" id="m18-c2-answer"><p class="sas-item__head"><strong>M18-C2</strong> <span class="sas-meta">Conceptual · 5 marks</span></p><p class="sas-answer__q">A team wants to skip evidence preservation to restore service faster. Argue the trade-off and the decision rule.</p><p class="sas-answer__label">Model answer</p><p>Restoring service quickly reduces customer harm, while preserving evidence determines whether the organisation can establish scope, notify affected parties and prevent recurrence. The rule is to preserve the minimum needed for those three purposes at the moment of containment, which is usually a snapshot of the filesystem, the relevant logs and the artefact digest rather than a full forensic image. Skipping preservation converts a contained incident into an open question, and regulatory obligations may make that question expensive.</p></div>

<div class="sas-answer" id="m18-sc1-answer"><p class="sas-item__head"><strong>M18-SC1</strong> <span class="sas-meta">Scenario-based · 6 marks</span></p><p class="sas-answer__q">At 02:00 a monitoring alert shows one principal issuing 40,000 near-duplicate queries. Write the first four actions in order.</p><p class="sas-answer__label">Model answer</p><p>First, preserve: snapshot logs and the query sample before any change. Second, contain: throttle or block the principal and, if the pattern suggests a compromised key, revoke the credential while keeping other traffic served. Third, assess: determine which model and data the queries reached and whether outputs were returned at full precision. Fourth, notify: inform the on-call lead and the owner of the model's IP, and start the incident record with times and evidence locations. Blocking before snapshotting risks losing the only record of what was taken.</p></div>

<div class="sas-answer" id="m18-sc2-answer"><p class="sas-item__head"><strong>M18-SC2</strong> <span class="sas-meta">Scenario-based · 6 marks</span></p><p class="sas-answer__q">A deployed model bundle is found to have been tampered with three weeks ago. Describe the recovery sequence and the checks that close it.</p><p class="sas-answer__label">Model answer</p><p>Quarantine the running artefact while preserving a copy, rebuild from the signed source, verify every hash against the manifest through an independent channel, and compare behaviour with a reference on a fixed probe set. Rotate any credential the compromised container could reach, and review access logs for the exposure window to establish what was served or read. Close the incident only when identity, behaviour, credentials and root cause each have evidence and an owner, and record what remains undetermined.</p></div>

<div class="sas-answer" id="m18-p1-answer"><p class="sas-item__head"><strong>M18-P1</strong> <span class="sas-meta">Practical programming · 8 marks</span></p><p class="sas-answer__q">Implement a principal-level detector over gateway logs that scores query similarity, failure rate and export volume, flags the abusive principal, and reports its precision against a labelled set.</p><p class="sas-answer__label">Model answer</p><p>A complete implementation aggregates per principal, computes robust z-scores for each signal, requires at least two signals above threshold and ranks principals. It reports the flagged set against the known abusive principal, giving precision and recall, and prints the contributing signals for each flag so an analyst can see why. A strong answer adds the false-positive rate on honest traffic and notes that a detector with one labelled positive gives a precise but not generalisable estimate.</p></div>

<div class="sas-answer" id="m18-ct1-answer"><p class="sas-item__head"><strong>M18-CT1</strong> <span class="sas-meta">Critical thinking · 6 marks</span></p><p class="sas-answer__q">A board asks for a single 'security score' for the AI platform. Construct the response.</p><p class="sas-answer__label">Model answer</p><p>A single score hides the differences that matter: a platform may be strong on boundary controls, weak on retrieval isolation and untested on extraction. Offer a small set of decision-relevant measures instead, each with its method and trend, such as tested injection success rate, retrieval isolation test status, artefact verification coverage and mean time to contain. The board's need is comparability over time and across releases, which a set of stable measures provides; a composite index destroys the information required to choose where to spend next.</p></div>

<div class="sas-answer" id="m18-ct2-answer"><p class="sas-item__head"><strong>M18-CT2</strong> <span class="sas-meta">Critical thinking · 6 marks</span></p><p class="sas-answer__q">You have telemetry for everything but no runbooks. Argue which to build first and why.</p><p class="sas-answer__label">Model answer</p><p>Runbooks first if incidents are recurring and the team lacks a consistent response, because detection without a procedure produces improvised containment that destroys evidence and lengthens outages. Telemetry first if the platform is new and nobody knows what normal looks like, since a runbook for an undetected event is unusable. The decision rule is whether the binding constraint is knowing or acting; the strongest answer names both, then states the evidence that would change the order, such as an incident review showing slow containment despite good alerts.</p></div>
