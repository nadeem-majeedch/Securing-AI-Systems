# Laboratory safety final review

**All 32 briefs re-read, with their claims checked against what each solution actually does.** Sections 18–22 were
compared against the lab's dataset section, the files and processes its solution creates, and the network behaviour it
exercises. Two claims were wrong and are fixed; the rest hold.

This is an editorial and technical review of written safety instructions. **It is not a security certification, and
no external auditor has seen this course.** The review establishes that the instructions are accurate and specific; it
does not establish that the course is safe for every reader, and the site must not imply otherwise.

## 1. The four labs named for special attention

### L08 — adversarial perturbations on digits

| Question | Finding |
|---|---|
| Acceptable use | Names the actual target: perturbations for the local classifier. States the purpose is measuring a model, not attacking a service. **Accurate.** |
| Scope | Forbids deployed recognisers, CAPTCHAs, document scanners, systems the reader does not own, and uploading crafted images. **Complete for the technique.** |
| Data handling | Identifies `digits_subset.npz` as a third-party UCI extract under CC BY 4.0 and requires the provenance note to travel with a copy. **Accurate** — verified against `ATTRIBUTION.md` §6. |

| Environment restore | "The pinned PyTorch wheel is all this lab needs." Verified: imports are NumPy, torch, sklearn only. **Accurate.** |

### L21 — RAG retrieval that leaks one document

| Question | Finding |
|---|---|
| Acceptable use | Restricts the exercise to the local index built from `rag_documents.json` across the three synthetic tenants. **Accurate.** |
| Scope | Forbids ingesting real documents, customer records or an employer's knowledge base. **Appropriate**: the lesson is a tenancy-boundary bug, and a real corpus would turn a teaching exercise into a data-protection incident. |
| Data handling | Twelve synthetic documents, one carrying an instruction by design; retrieved text treated as untrusted. **Accurate** — the corpus is generated by `make_datasets.py`. |
| Cleanup | Vector-store directory or embeddings file, if the student made one; the solution keeps the index in memory. Verified: no writes in `L21/solution.py`. **Accurate.** |
| Environment restore | "No database service is required." Verified: no server, no external store. **Accurate.** |

### L26 — insecure prediction API and its hardened twin

| Question | Finding |
|---|---|
| Acceptable use | ASGI transport or `127.0.0.1` with uvicorn; local machine only. **Accurate** and the right default: the solution uses `httpx.ASGITransport` and never binds a port. |
| Scope | No `0.0.0.0`, no tunnels, the demo `x-api-key` is a fixture rather than a credential. **Accurate** — the key is a literal in the script, and saying so prevents the common mistake of copying it into a real config. |

| Cleanup | Stop uvicorn if started; delete request/response dumps. **Necessary and sufficient** — the failure mode is a forgotten background listener. |
| Environment restore | FastAPI, pydantic, httpx are pinned; no service left listening. **Accurate**; these are the only three packages the lab needs. |

### L30 — recovering from a compromised model

| Question | Finding |
|---|---|

No change was needed in these four. L32, reviewed alongside them because it consumes their evidence, did need a

## 2. Corrections made in this phase

**L01 — data handling contradicted the submission.** The text said not to paste rows into "an issue, a report or a
chat". The lab's expected results and submission require quoting referral identifiers as evidence. Rewritten: keep the
file in `labs/datasets/`, quote only the identifiers and fields needed as evidence in your own report, and do not paste
rows into a public issue, chat or shared document. This is the distinction that matters — the learner's own marking
copy is not a disclosure channel.

**L32 — provenance pointed at files that do not exist.** The dataset section and section 20 said evidence came from
"the referenced labs' outputs", and the solution labelled eight values with `labs/solutions/Lxx/output.txt` paths.
No such files exist. Both the brief and the ten source labels now say the values are carried in the starter and are
reproducible by running the named lab and reading its printed line.

## 3. The other 28 labs — generalisations checked

The review looked specifically for claims that were too broad, too narrow, or copied between labs.

| Claim type | Example | Verdict |
|---|---|---|
| "Work on your own machine" (all 32) | Standard opening line | **Accurate but generic**; every section that follows is lab-specific, so the sentence is a frame rather than the instruction |
| "Nothing leaves the notebook" (L17–L19) | Checked against solutions: no network calls, no writes | Accurate |
| "Do not use a real gateway log" (L29) | The lab replays a synthetic CSV | Accurate and specific |
| "Do not load a pickle … from an untrusted source" (L24) | The lab loads safetensors only; the pickle discussion is a release-gate table | Accurate — the rule is stricter than the lab, which is the right direction |
| "The mock has no network listener" (L16) | Verified: in-process mock | Accurate |
| "Training takes under a minute" (L25) | Measured: 4.1 s | Accurate |
| "If you add a row from real work, generalise it" (L28) | Invites real experience into a matrix | **Acceptable**, but it is the one place a student is pointed at their own engagement material; the instruction to remove client identifiers is explicit |
| "Regenerate the dataset if you altered it" (L02, L10, L07) | Matches `make_datasets.py` determinism | Accurate |

Fourteen labs state "nothing is installed" or "core stack only" for environment restoration. That was checked against
their imports: none needs a package outside the pinned twelve, with the single optional exception of Ollama in the M11
notebook, which is not a lab.

Nothing in the 28 sets a permission broader than the course-wide rules, and the three that discuss credential
material (L26, L30, L24) all say the fixture is not a credential.

## 4. Safety posture, honestly stated

**What is true:**

- Every lab targets synthetic data, a model trained inside the lab, or an in-process mock service.
- No lab requires or authorises testing against a third-party system.
- No lab makes a network request at run time; `pip` at install time is the only fetch.
- Credentials, keys and tokens in the labs are written as fixtures, and each is labelled as one.
- Data handling distinguishes third-party data (the digits extract), sensitive-shaped synthetic fields (admissions,
  patient extracts) and instruction-bearing text (referral notes, one RAG document).

**What is not claimed:**

- That the course has been security-certified, audited by a professional body, or endorsed by any institution.
- That a student who follows the labs is authorised to repeat them elsewhere; section 19 of every brief says the
  opposite.
- That the synthetic data is anonymous in any legal sense — it is synthetic, which is stronger, and the briefs say so.

**Residual risk:** the safety sections are prose, and a determined reader can ignore prose. What the course controls
is the environment: there is no live target to misuse, no credential to steal and no network path to a third party.
That is a stronger control than any warning paragraph.
